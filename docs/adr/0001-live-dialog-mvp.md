# Live-Dialog statt Capture-Only als MVP-Kern

Ursprünglich war für den MVP ein reiner Erfassungsmodus vorgesehen (Nutzer spricht, KI transkribiert, antwortet nicht live), mit einem vollen zweiseitigen Sprachdialog als spätere Ausbaustufe. Diese Entscheidung wird umgekehrt: echter Live-Dialog — die KI hört zu, erkennt echte Fragen, antwortet live mit gezieltem Retrieval, fragt bei Unsicherheit kurz nach — ist das Kernversprechen des Produkts ("ins Auto steigen, 20 Minuten mit der KI reden wie mit einem Kollegen, sie erinnert sich zuverlässig") und damit MVP-Pflicht, kein Nebenfeature.

Um das stabil bauen zu können, werden im Gegenzug GraphRAG, ausgefeilte Entity-Deduplizierung (MVP bleibt bei exaktem Match + Alias-Liste + manuell bestätigten Fuzzy-Vorschlägen), automatische Workflows, komplexe Analytics und feingranulare Rollen (MVP bleibt bei den drei Grundrollen Owner/Editor/Viewer) aus dem MVP gestrichen bzw. auf die einfachste Variante reduziert. Memory-Extraction bleibt bewusst nachgelagert (nicht Teil der Live-Session), damit der Dialog flüssig bleibt — nur Retrieval bekommt zusätzlich zum Batch-Pfad einen live-tauglichen, gezielten Abfragepfad während der Realtime-Session.

Aus demselben Grund wird auch der Einladungsmechanismus für Context Spaces für den MVP komplett gestrichen (kein Invite-Flow, keine Multi-Member-UI). Supabase Auth bleibt aktiv, und das Datenbankschema wird bereits multi-user-fähig angelegt (Rollen, Freigabestatus, Sichtbarkeit), aber jede Context Space hat im MVP faktisch genau ein Mitglied — den Owner. Aktiviert wird das in V2, ohne Schemaänderung.
